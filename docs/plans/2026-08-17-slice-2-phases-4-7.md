# Yourly Slice 2 (Phases 4–7) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: superpowers:executing-plans. Conventions (build/test commands,
> commit-per-green-step, re-run `xcodegen generate` on structural source changes) are in the slice-1
> plan and unchanged. Simulator: `iPhone 17 Pro`.

**Goal:** Complete the local (no voice/backend) product loop — swipe-delete + Undo, search, calendar
navigation, and settings with Face ID privacy lock — on top of the slice-1 typed-notes app.

**Architecture:** Same feature-oriented SwiftUI + SwiftData app. Home converts to a chromeless `List`
so native swipe actions work. New `NoteStore` methods (`undoDelete`, `purgeDeleted`, `notes(on:)`,
`noteDays(in:)`) keep logic testable. Face ID via `LocalAuthentication`; privacy cover via scene phase.

**Tech Stack:** Swift 6.2, SwiftUI, SwiftData, LocalAuthentication, Swift Testing, XcodeGen, iOS 26.

## Phase 4 — Delete + Undo

**Files:** modify `Core/Persistence/NoteStore.swift`, `SwiftDataNoteStore.swift`,
`Features/Home/HomeTimeline.swift`, `Features/Home/HomeView.swift`; create
`Core/DesignSystem/UndoBanner.swift`, `Features/Home/HomeModel.swift`; tests `NoteStoreDeleteTests.swift`.

- NoteStore gains `undoDelete(_:)` (deletedAt = nil), `purgeDeleted()` (hard-delete all deletedAt != nil).
- App calls `purgeDeleted()` once at launch (expired soft-deletes from prior sessions).
- Home timeline becomes a `List` with `.plain` style, hidden separators, canvas row background, custom
  insets → keeps the chromeless look while enabling `.swipeActions` destructive Delete.
- On delete: soft-delete + show `UndoBanner` (“Note deleted   Undo”) for ~4s; Undo restores exactly.
- **Tests:** soft-delete then undoDelete restores title/body/dates; purgeDeleted removes soft-deleted
  and keeps live; recent() still excludes soft-deleted.
- **Done:** swipe reveals red Delete; row disappears; Undo restores; relaunch purges un-undone deletes.

## Phase 5 — Search

**Files:** create `Core/Persistence/NoteSearch.swift` (pure filter) + `Features/Search/SearchResultsView.swift`,
`Features/Search/SearchResultRow.swift`; modify `HomeView.swift`; tests `NoteSearchTests.swift`.

- Pure `matches(_ note:query:)` / `searchNotes(_:query:)`: case- and diacritic-insensitive
  (`.caseInsensitive, .diacriticInsensitive`), Unicode-safe, matches normalized title + body; empty
  query → empty results (Home shows normally).
- `.searchable` on Home; when `isSearching`, show `SearchResultsView` (flat list: title/first line +
  excerpt + **date** — dates shown in search though hidden on Home rows). Tapping opens the editor.
- **Tests:** case-insensitive Latin; Telugu + Hindi Unicode queries; matches body and title; empty
  query returns empty; diacritic-insensitive.
- **Done:** search filters notes live; result shows date; selecting opens the note; empty query =
  normal Home.

## Phase 6 — Calendar

**Files:** create `Features/Calendar/CalendarSheet.swift`, `Features/Calendar/MonthGrid.swift`,
`Core/Persistence/MonthDays.swift` (pure month/day math); modify `SwiftDataNoteStore.swift`
(`notes(on:)`, `noteDays(in:)`), `HomeView.swift` (calendar button presents sheet, selected-day filter,
Return to Today); tests `MonthDaysTests.swift`.

- Pure helpers: `daysInMonthGrid(for:calendar:)` (leading blanks + day cells), `startOfMonth`,
  month add/subtract — all Calendar-based (no 24h math).
- `noteDays(in month:)` → Set of startOfDay for days with ≥1 live note; `notes(on day:)` → that day’s
  notes via a date-interval predicate.
- CalendarSheet: month header + prev/next, weekday row, grid with a dot on days with notes, selected
  day highlighted (accent circle), Today distinguished. Selecting a day dismisses and filters Home to
  that day with a “Return to Today” affordance.
- **Tests:** month rollover (Dec→Jan), year rollover, timezone/DST day count, empty day → no dot,
  many notes same day → single dot, noteDays set correctness.
- **Done:** calendar button opens sheet; dots correct; tap day filters Home; Return to Today restores.

## Phase 7 — Settings + privacy lock

**Files:** create `Features/Settings/SettingsView.swift`, `Features/AppLock/AppLockService.swift`,
`Features/AppLock/LockView.swift`, `Features/AppLock/PrivacyCover.swift`; modify `AppRootView.swift`,
`YourlyApp.swift`, `HomeView.swift` (settings entry); tests `AppLockStateTests.swift`.

- SettingsView: PRIVACY (`Lock with Face ID` toggle, `@AppStorage("appLockEnabled")`) and ABOUT
  (Privacy Policy, About [AppName], Version 1.0.0). Presented from Home (e.g. overflow/settings button).
- AppLockService (`@Observable`): `locked` state machine; `authenticate()` via `LAContext`
  `.deviceOwnerAuthentication` (biometric + passcode fallback); enable requires a successful auth.
- On scene not-active with lock enabled → show `PrivacyCover` (mark only, no readable notes) before the
  system snapshot; on return → `LockView` requires auth before revealing content.
- **Tests (pure state machine, LAContext injected/mocked):** enable requires success; failure keeps
  locked/undisclosed; background sets covered; foreground requires auth; cancel leaves locked.
- **Done:** toggle enables with Face ID; background covers content; app-switcher snapshot protected;
  foreground re-auth reveals; cancel/failure never exposes notes.
